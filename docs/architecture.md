# Creative Art Studio architecture

Creative Art Studio is a browser-local React application designed to make the core creative journey reliable without collecting personal information. The central design boundary is between the **creative engine**, which holds structured scene data, and the **interface**, which adapts the same engine for Explorer, Creator, and Designer modes.

| Layer                | Location                                                                                 | Responsibility                                                                                                                                                                                                  |
| -------------------- | ---------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Application routes   | `client/src/App.tsx`, `client/src/pages/`                                                | Keeps the public field-journal routes light while lazy-loading the Three.js studio entry.                                                                                                                       |
| Creative interface   | `client/src/components/studio/`                                                          | Presents the maker shelf, canvas, inspector, gallery, tutorial, and reflection flow.                                                                                                                            |
| Creative state       | `client/src/store/useStudioStore.ts`                                                     | Owns reversible scene changes, saved artwork metadata, age preferences, and browser-local actions.                                                                                                              |
| Data boundaries      | `client/src/types/studio.ts`, `client/src/lib/studioPersistence.ts`                      | Defines structured scene records and validates LocalStorage before persistence is merged into the app.                                                                                                          |
| Gallery organization | `client/src/lib/galleryOrganization.ts`                                                  | Provides independently tested folder, tag, search, and favourites filtering logic.                                                                                                                              |
| Production host      | `server/index.ts`, `server/health.ts`, `server/schemas.ts`, `server/errorSink.ts`        | Serves the static bundle, explicitly wires `GET /healthz`, validates `GET /metrics` queries, records privacy-safe metrics, and supports an opt-in local JSONL error sink without requiring an external account. |
| Scene rendering      | `client/src/components/studio/StudioCanvas.tsx`, `StudioSceneObjects.tsx`                | Keeps canvas orchestration separate from object geometry, materials, selection, and transform controls.                                                                                                         |
| Scene construction   | `client/src/store/sceneBuilders.ts`                                                      | Creates default and surprise compositions independently from the main Zustand store.                                                                                                                            |
| Offline delivery     | `client/src/lib/offline.ts`, `client/public/sw.js`, `client/public/manifest.webmanifest` | Registers a root-scoped service worker, caches the production app shell and same-origin runtime assets, and falls back to the cached dashboard for navigation when offline.                                     |

## Persistence and privacy

Artwork configurations, gallery metadata, settings, and the most recent short reflection are stored only in the current browser’s LocalStorage. The persistence parser treats that data as untrusted: malformed payloads are ignored, and compatible earlier object records receive safe defaults for later-added texture and sticker fields. The service worker caches only same-origin application resources; it does not cache personal data, external API responses, or credentials. Offline access is therefore device-local and dependent on a prior successful visit. No account, analytics, public sharing, location, or server-side artwork storage is included in this release.

## Quality boundaries

`pnpm quality:ci` runs formatting, lint, type checking, unit tests with 70% line/statement/branch coverage gates, the production dependency audit, and the production build. `pnpm test:e2e` runs the Playwright creative flow separately, while `bash scripts/verify-fresh-clone.sh` verifies the frozen install, Chromium availability, coverage run, production build, production-asset assertion, and browser flow from a clean checkout. The CI workflow runs these checks on clean lockfile installations, uploads coverage, browser, dependency-freshness, and fresh-clone artifacts, reviews pull-request dependency changes, and smoke-tests the production container at `/healthz` and `/metrics`. The optional map integration is offline-first: without `VITE_FRONTEND_FORGE_API_KEY`, it does not append a remote script and marks its container unavailable. The server validates unsupported metrics query parameters with a safe 400 contract, normalizes unknown thrown values, rejects unsafe request IDs, and `ERROR_TRACKING_FILE` enables a local structured JSONL error trail that creates its parent directory, serializes writes, bounds field sizes, and redacts sensitive query values when explicitly configured. Generated Manus browser-debug instrumentation is kept as modular files under `tools/dev-only/debug-collector/`, excluded from application linting and formatting, and served by the Vite development middleware only. Production builds do not copy it into `dist/public`, keeping runtime support code separate from authored studio logic and shipped assets.
